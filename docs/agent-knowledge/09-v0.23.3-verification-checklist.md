## 1. Pre-publish prerequisites (all must hold)

- [ ] **All rc gate jobs green.** Every rc gate job for the release candidate is
      `success`. Human-only/skipped gates must be explicitly identified, not silently
      treated as green. A flaky gate is a failure until reproduced and stabilized;
      do not retry merely to obtain green.
- [ ] **No unresolved blockers.** No open hard-stop findings (integrity, branding,
      security, provenance, candidate-test, ZIP-audit, conformance) and no unaddressed
      release-blocking issue.
- [ ] **Publish/autopublish path completed as configured.** The configured release
      path (`python3 scripts/release.py publish --version v0.23.3`, or the
      `--autopublish` flow where that is the configured mode) has run to completion.
      PREVIEW must have been reviewed before any PUBLISH decision; PUBLISH is a human
      action performed only after approval. Record the run/sequencer output.
- [ ] **Correct target branch and identity.** Release produced from the approved
      protected branch (`main`) and the tag points at the intended release commit.

## 2. API verification (run and capture output before declaring success)

Run from a checkout with `gh` authenticated to the target repo.

### 2.1 Release exists, published, not draft, not prerelease

```bash
gh release view v0.23.3 --repo nastechresearch/nastech-agent \
  --json tagName,isDraft,isPrerelease,publishedAt,body,assets

gh api repos/nastechresearch/nastech-agent/releases/tags/v0.23.3 \
  --jq '{tag:.tag_name, draft:.draft, prerelease:.prerelease, published_at:.published_at}'
```

Expected: `isDraft=false`, `isPrerelease=false`, `publishedAt` non-null,
tag exactly `v0.23.3`.

### 2.2 Builds table present in release body

Inspect the `body` returned above. Expected: a builds/installers table listing the
released assets (platform targets, file names, and checksums such as SHA-256), readable
and not empty.

```bash
gh release view v0.23.3 --repo nastechresearch/nastech-agent --json body --jq .body \
  | grep -inE 'sha256|checksum|\|.*(linux|macos|windows|\.zip|\.tar\.gz)' || echo 'NO BUILDS TABLE FOUND'
```

### 2.3 R2-backed assets resolve HTTP 200

```bash
gh api repos/nastechresearch/nastech-agent/releases/tags/v0.23.3 \
  --jq '.assets[].browser_download_url' | while read -r url; do
    code=$(curl -s -o /dev/null -w '%{http_code}' -L "$url")
    printf '%s  %s\n' "$code" "$url"
  done
```

Expected: every asset returns `200`. Any non-200 is a hard stop.

### 2.4 Check-runs green on the release commit

```bash
SHA=$(git rev-parse v0.23.3^{commit})
gh api "repos/nastechresearch/nastech-agent/commits/$SHA/check-runs" \
  --jq '.check_runs[] | [.name, .status, .conclusion] | @tsv'
```

Expected: all conclusions `success` (human-only/skipped gates documented in §1).
Optionally also confirm the rc gate run jobs directly:

```bash
gh api repos/nastechresearch/nastech-agent/actions/runs/<RC_GATE_RUN_ID>/jobs \
  --jq '.jobs[] | [.name, .conclusion] | @tsv'
```

### 2.5 Receipt and tag refs resolve

```bash
git rev-parse v0.23.3^{commit}                          # local tag resolves
git ls-remote --tags origin refs/tags/v0.23.3          # remote tag resolves
# For any receipt file or commit SHA referenced by the release body/artifacts:
git cat-file -e <referenced-sha>^{commit} && echo 'ref resolves'
```

Expected: every referenced tag/SHA resolves locally and on the remote.

### 2.6 No attribution hints in release notes/body

```bash
gh release view v0.23.3 --repo nastechresearch/nastech-agent --json body --jq .body \
  | grep -inE 'attribut|generated by|co-authored-by|authored by (ai|an ai)|\b(claude|anthropic)\b' \
  || echo 'no attribution hints'
```

Expected: no matching attribution hints. If a hint is found, correct the release body
before proceeding.
